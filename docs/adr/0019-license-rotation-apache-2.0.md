## Context / Contexto

**EN:** [ADR-0007](0007-license-mpl-2.0.md) relicensed the whole project from AGPL-3.0 to MPL-2.0 on 2026-06-28, reasoning that glintfx is meant for **external adoption** and that AGPL's linking-as-derivative-work stance plus its network clause (§13) is poison for that goal. MPL-2.0 struck a balance: weak per-file copyleft on the project's own files, plus a patent grant, while letting third parties (including proprietary apps) link freely. That ADR explicitly named the window this decision now uses: *"Relicensing is clean now because petrus is the sole author. It must happen before accepting external contributions (otherwise it needs consent from all contributors or a CLA)."*

That window is still open. No external contribution has landed since 2026-06-28; every commit in the repository's history traces to the same one person, petrus, even though that person used two different git identities over time (see Evidence below, which shows the raw split rather than a rounded-off "single identity" claim). The project's own direction has also sharpened since then: [ADR-0015](0015-framework-2d-atomized-architecture.md) and the wider roadmap in `TODO.md` commit glintfx to a **2D application framework meant for broad, general-purpose distribution** (the líder's ongoing "framework2d" direction, tracked in this project's own operating memory rather than a repo file; per the same standing policy recorded in `TODO.md`'s `GLLOADER-HOST` item, quality and scope decisions already target the general audience, not the one known consumer). A framework whose stated goal is wide adoption benefits from the license with the widest, most familiar adoption footprint: **Apache-2.0** is the single most common permissive license for infrastructure and framework-shaped OSS (kernels, cloud-native projects, most of the Apache Software Foundation's own catalogue, Kubernetes, TensorFlow, and a large share of corporate open-source policy allowlists default to accepting it without legal review, where MPL-2.0's weak per-file copyleft sometimes still triggers one).

**Dependency compatibility, checked, not assumed:** every dependency this project links, vendors, or consumes is permissive and compatible with an Apache-2.0 outbound license, because glintfx **links, not copies** (ADR-0007's own reasoning, unchanged): RmlUi (MIT), FreeType (FTL), libGL (MIT/SGI-style), GLFW (zlib), stb_image / stb_image_write (public domain / MIT), miniaudio (MIT-0), SDL_GameControllerDB (zlib, consumed as **data**, not code), glcorearb.h / khrplatform.h (MIT). One dependency is already Apache-2.0 itself: the Khronos `gl.xml` registry that `tools/gen_glloader.py` mechanically derives glintfx's own GL loader from.

**Scope, precisely:** the project has a **single `LICENSE`/`NOTICE` pair at the repository root**, applied to the whole project per ADR-0007's own text ("Relicense the whole project"), covering both Layer 0 (`loucura_c_asm`, the sovereign C+ASM core, `src/`/`include/`/`tests/`/`tools/` at the root) and Layer 1 (`glintfx/`). This ADR rotates that same single pair; it is **not** glintfx-only, even though glintfx is the active product and the practical trigger for this decision.

**PT:** o [ADR-0007](0007-license-mpl-2.0.md) relicenciou o projeto inteiro de AGPL-3.0 para MPL-2.0 em 2026-06-28, com o raciocínio de que o glintfx é feito para **adoção externa** e que a postura da AGPL (link como obra derivada, mais a cláusula de rede §13) é veneno para esse objetivo. A MPL-2.0 equilibrou: copyleft fraco por-arquivo nos arquivos do próprio projeto, mais grant de patente, deixando terceiros (inclusive apps proprietários) linkarem livremente. Aquele ADR nomeou explicitamente a janela que esta decisão agora usa: *"Relicenciar é limpo agora porque o petrus é autor único. Precisa acontecer antes de aceitar contribuições externas (senão exige consentimento de todos ou um CLA)."*

Essa janela continua aberta. Nenhuma contribuição externa chegou desde 2026-06-28; todo commit no histórico do repositório remonta à mesma pessoa, o petrus, mesmo essa pessoa tendo usado duas identidades git diferentes ao longo do tempo (ver Evidência abaixo, que mostra a divisão bruta em vez de uma alegação arredondada de "identidade única"). A própria direção do projeto também se afiou desde então: o [ADR-0015](0015-framework-2d-atomized-architecture.md) e o roadmap mais amplo no `TODO.md` comprometem o glintfx a um **framework de aplicação 2D feito para distribuição ampla e de propósito geral** (a direção "framework2d" em andamento do líder, rastreada na memória operacional deste projeto, não num arquivo do repositório; pela mesma política permanente registrada no item `GLLOADER-HOST` do `TODO.md`, decisões de qualidade e escopo já miram o público amplo, não o único consumidor conhecido). Um framework cujo objetivo declarado é adoção ampla se beneficia da licença com a pegada de adoção mais ampla e familiar: a **Apache-2.0** é a licença permissiva mais comum para OSS em forma de infraestrutura/framework (kernels, projetos cloud-native, boa parte do próprio catálogo da Apache Software Foundation, Kubernetes, TensorFlow, e uma fatia grande das listas de permissão jurídica corporativas já aceita ela sem revisão jurídica, onde o copyleft fraco por-arquivo da MPL-2.0 às vezes ainda dispara uma).

**Compatibilidade de dependência, verificada, não presumida:** toda dependência que este projeto linka, vendoriza ou consome é permissiva e compatível com uma saída Apache-2.0, porque o glintfx **linka, não copia** (o mesmo raciocínio do ADR-0007, inalterado): RmlUi (MIT), FreeType (FTL), libGL (estilo MIT/SGI), GLFW (zlib), stb_image / stb_image_write (domínio público / MIT), miniaudio (MIT-0), SDL_GameControllerDB (zlib, consumido como **dado**, não código), glcorearb.h / khrplatform.h (MIT). Uma dependência já é Apache-2.0 ela mesma: o registro Khronos `gl.xml`, de onde o `tools/gen_glloader.py` deriva mecanicamente o próprio loader GL do glintfx.

**Escopo, com precisão:** o projeto tem um **único par `LICENSE`/`NOTICE` na raiz do repositório**, aplicado ao projeto inteiro pelo próprio texto do ADR-0007 ("Relicenciar o projeto inteiro"), cobrindo tanto a Camada 0 (`loucura_c_asm`, o núcleo soberano C+ASM, `src/`/`include/`/`tests/`/`tools/` na raiz) quanto a Camada 1 (`glintfx/`). Este ADR rotaciona esse mesmo par único; **não** é só-glintfx, mesmo o glintfx sendo o produto ativo e o gatilho prático desta decisão.

## Decision / Decisão

**EN:** Rotate the project's outbound license, **project-wide**, from `MPL-2.0` to **`Apache-2.0`** (Apache License, Version 2.0), effective **from a cut tag forward, not retroactively**.

- **`LICENSE` text, verified by diff, not by reading.** The repository's `LICENSE` file is the official Apache-2.0 text, unedited. Verified with `curl -fsS https://www.apache.org/licenses/LICENSE-2.0.txt -o /var/tmp/apache-2.0-oficial.txt` (202 lines) followed by `diff /var/tmp/apache-2.0-oficial.txt LICENSE`: **identical, zero diff output**, run by a teammate with shell access. (An earlier pass of this ADR had offered a model's own recollection of the canonical text as if it were that verification; recorded here as the corrected, actually-run check, not the recollection.)
- **Forward-only, never retroactive.** All **44 tags already published** under MPL-2.0 (`v0.1.0` through the latest at the time of this ADR) keep MPL-2.0 **forever** — history is not rewritten, and no attempt is made to relicense a distributed artifact after the fact. Apache-2.0 governs the source tree **from the cut point onward**.
- **Cut point:** **`v0.29.0`**. This paragraph does not embed a literal commit SHA -- it is itself part of the tree the tag covers, so a self-embedded SHA can never converge (editing the text changes the hash, which would need to be embedded again). **`git rev-parse v0.29.0` is the authoritative way to resolve the exact commit.**
- **A single, seamless swap, not dual-licensing.** The project does not adopt an MPL-2.0-OR-Apache-2.0 dual scheme going forward. The 44 already-published MPL-2.0 tags already function, in effect, as the "if you need MPL's terms, pin an old tag" option for anyone who genuinely needs it (see the GPLv2 trade-off below) — a formal dual-license going forward would add real, ongoing maintenance cost (two license headers to keep straight, two compliance postures to explain to adopters) for a need with no known consumer today.

**PT:** Rotacionar a licença de saída do projeto, **em todo o repositório**, de `MPL-2.0` para **`Apache-2.0`** (Apache License, Version 2.0), com vigência **a partir de uma tag de corte em diante, não retroativa**.

- **Texto do `LICENSE`, verificado por diff, não por leitura.** O arquivo `LICENSE` do repositório é o texto oficial da Apache-2.0, sem edição. Verificado com `curl -fsS https://www.apache.org/licenses/LICENSE-2.0.txt -o /var/tmp/apache-2.0-oficial.txt` (202 linhas) seguido de `diff /var/tmp/apache-2.0-oficial.txt LICENSE`: **idêntico, diff vazio**, rodado por um colega de equipe com acesso a shell. (Uma passada anterior deste ADR tinha oferecido a lembrança de um modelo sobre o texto canônico como se fosse essa verificação; fica registrado aqui como a checagem corrigida e de fato rodada, não a lembrança.)
- **Só pra frente, nunca retroativo.** As **44 tags já publicadas** sob MPL-2.0 (`v0.1.0` até a mais recente no momento deste ADR) mantêm MPL-2.0 **para sempre** — o histórico não é reescrito, e nenhuma tentativa é feita de relicenciar um artefato já distribuído depois do fato. A Apache-2.0 rege a árvore de fonte **a partir do ponto de corte em diante**.
- **Ponto de corte:** **`v0.29.0`**. Este parágrafo não embute um SHA literal de commit -- ele faz parte da própria árvore que a tag cobre, então um SHA autoembutido nunca converge (editar o texto muda o hash, que precisaria ser embutido de novo). **`git rev-parse v0.29.0` é a forma autoritativa de resolver o commit exato.**
- **Uma troca única e seca, não dual-license.** O projeto não adota um esquema dual MPL-2.0-OU-Apache-2.0 daqui pra frente. As 44 tags MPL-2.0 já publicadas já funcionam, na prática, como a opção "se precisar dos termos da MPL, pina numa tag antiga" para quem genuinamente precisar (ver o trade-off de GPLv2 abaixo) — um dual-license formal daqui pra frente somaria custo real e contínuo de manutenção (dois headers de licença para manter certos, duas posturas de conformidade para explicar a quem adota) para uma necessidade sem consumidor conhecido hoje.

### Four decisions of form / Quatro decisões de forma

**EN:**

1. **SPDX header only, no 13-line boilerplate comment.** Every source file will carry `SPDX-License-Identifier: Apache-2.0` (rotated from `SPDX-License-Identifier: MPL-2.0` by `APACHE-HEADERS`), and nothing more. The Apache-2.0 Appendix's full boilerplate notice is explicitly **recommended, not required** by the license text itself ("attach the following boilerplate notice" is guidance for applying the license, not a term of it); `LICENSE` at the repository root already satisfies §4(a)'s "give recipients a copy of this License". SPDX-only is the practice of the Linux kernel and the [REUSE](https://reuse.software/) specification this project already aligns with (`tools/check_spdx.sh` already greps for the single-line form; keeping that shape means the existing gate only needs its literal string updated, not a structural rewrite). ⚠️ **Scope note, not this ADR's to fix:** `tools/check_spdx.sh` as it exists today only walks Layer 0's `src`/`include`/`tests`/`tools` at the repository root, by its own file header ("Scoped to Layer 0 ... does NOT walk glintfx/"); glintfx has its own SPDX enforcement. `APACHE-HEADERS` is responsible for updating **both** gates' literal string, not just one.
2. **§4(b) ("modified files must carry prominent notice"): the git commit history is that notice.** Recorded operationally in [`CONTRIBUTING.md`](../../CONTRIBUTING.md)'s "Licensing of contributions" section (both languages). §4(b) binds **redistributors of a Derivative Work**, not this project's own commits to its own tree — but stating the position in `CONTRIBUTING.md` removes any ambiguity for a downstream fork that modifies files and redistributes them: git history is the accepted notice mechanism, no per-file changelog comment is expected.
3. **`NOTICE` enxuto (lean), the rest moved to `docs/third_party_notices.md`.** Apache-2.0 §4(d) makes `NOTICE`'s content **mandatory propagation** for anyone redistributing the work; the pre-rotation `NOTICE` carried roughly 150 lines of prose, acknowledgment narrative, and patch-disclosure detail. Under Apache-2.0 that entire block becomes a compulsory burden on every redistributor, not an informational courtesy. `NOTICE` now carries only: project name, copyright line, the license grant statement, and the attributions each dependency's **own license actually requires** (RmlUi/MIT, FreeType/FTL, GLFW/zlib, SDL_GameControllerDB/zlib, glcorearb.h+khrplatform.h/MIT, Open Sans/Apache-2.0). stb_image, stb_image_write, and miniaudio are MIT-0 / public-domain-as-used and do not themselves require attribution; they get one disclosure line each, not a required-notice paragraph. Nothing was deleted, the full prose lives in [`docs/third_party_notices.md`](../third_party_notices.md), a plain doc with no §4 obligation attached to it.
4. **Troca seca, not dual-license.** See "A single, seamless swap" above.

**PT:**

1. **Só o header SPDX, sem o comentário boilerplate de 13 linhas.** Todo arquivo-fonte vai carregar `SPDX-License-Identifier: Apache-2.0` (rotacionado de `SPDX-License-Identifier: MPL-2.0` pelo `APACHE-HEADERS`), e nada além disso. O aviso boilerplate completo do Apêndice da Apache-2.0 é explicitamente **recomendado, não exigido** pelo próprio texto da licença ("attach the following boilerplate notice" é orientação para aplicar a licença, não um termo dela); o `LICENSE` na raiz do repositório já satisfaz o §4(a) ("dar aos destinatários uma cópia desta License"). Só-SPDX é a prática do kernel Linux e da especificação [REUSE](https://reuse.software/) à qual este projeto já se alinha (`tools/check_spdx.sh` já grepa a forma de linha única; manter essa forma significa que o gate existente só precisa da string literal atualizada, não de uma reescrita estrutural). ⚠️ **Nota de escopo, não é deste ADR consertar:** o `tools/check_spdx.sh`, como existe hoje, só varre `src`/`include`/`tests`/`tools` da Camada 0 na raiz do repositório, pelo próprio cabeçalho do arquivo ("Escopo restrito à Camada 0 ... NÃO varre glintfx/"); o glintfx tem sua própria fiscalização de SPDX. O `APACHE-HEADERS` é responsável por atualizar a string literal dos **dois** gates, não só de um.
2. **§4(b) ("arquivos modificados devem carregar aviso proeminente"): o histórico de commits do git É esse aviso.** Registrado operacionalmente na seção "Licença das contribuições" do [`CONTRIBUTING.md`](../../CONTRIBUTING.md) (nos dois idiomas). O §4(b) obriga **quem redistribui uma Obra Derivada**, não os próprios commits deste projeto na própria árvore, mas declarar a posição no `CONTRIBUTING.md` remove qualquer ambiguidade para um fork downstream que modifique arquivos e os redistribua: o histórico do git é o mecanismo de aviso aceito, nenhum comentário de changelog por-arquivo é esperado.
3. **`NOTICE` enxuto, o resto mudou para `docs/third_party_notices.md`.** O §4(d) da Apache-2.0 torna o conteúdo do `NOTICE` **propagação obrigatória** para quem redistribui a obra; o `NOTICE` pré-rotação carregava cerca de 150 linhas de prosa, narrativa de agradecimento e detalhe de divulgação de patch. Sob Apache-2.0, esse bloco inteiro vira fardo compulsório para todo redistribuidor, não uma cortesia informativa. O `NOTICE` agora carrega só: nome do projeto, linha de copyright, a declaração de concessão de licença, e as atribuições que a **própria licença** de cada dependência de fato exige (RmlUi/MIT, FreeType/FTL, GLFW/zlib, SDL_GameControllerDB/zlib, glcorearb.h+khrplatform.h/MIT, Open Sans/Apache-2.0). stb_image, stb_image_write e miniaudio são MIT-0 / domínio-público-como-usados e não exigem atribuição por si; recebem uma linha de divulgação cada, não um parágrafo de aviso obrigatório. Nada foi apagado, a prosa inteira vive em [`docs/third_party_notices.md`](../third_party_notices.md), um doc comum sem obrigação de §4 atrelada.
4. **Troca seca, não dual-license.** Ver "Troca única e seca" acima.

## The trade-off, stated honestly / O trade-off, declarado com honestidade

**EN:** Two real consequences of this rotation, named here rather than left implicit:

1. **The weak per-file copyleft is gone.** Under MPL-2.0, a modification to one of *this project's own* files stayed open under MPL-2.0 even if distributed inside a Larger Work. Under Apache-2.0, a downstream fork can modify a file and close it, without any obligation to publish the change. This is exactly what is being traded for wider adoption, and wider adoption **is** this framework's declared goal, not a side effect being rationalized after the fact.
2. **GPLv2 compatibility flips sign.** MPL-2.0 carries the "Secondary License" clause (License §3.3, Exhibit B not invoked in this project's own `LICENSE`) that lets Covered Software also be redistributed under GPL-2.0, LGPL-2.1, or AGPL-3.0 at the recipient's option. **Apache-2.0 does not have an equivalent clause and is widely held (FSF's own compatibility list, among others) to be incompatible with GPLv2**, while it **is** compatible with GPLv3 and later. A hypothetical consumer that is itself GPLv2 (not GPLv2-or-later) and wanted to statically link glintfx would lose that path. ✅ **No known consumer is affected today**, checked in each consumer's own repository, not by asking them: GusWorld is not GPLv2 (its own license is separate and unaffected by this decision); the Glyfesse site consumer is PHP+HTML with **zero linking surface** to glintfx at all (`git grep '#include.*glintfx'` = 0, `git grep 'glintfx::'` = 1 editorial-prose mention, `vendor/`/`third_party/`/`node_modules` = 0, per the `APACHE-AVISO` fatia's own verification recorded in `TODO.md`), so the GPLv2 question does not even arise for it.

**PT:** Duas consequências reais desta rotação, nomeadas aqui em vez de deixadas implícitas:

1. **O copyleft fraco por-arquivo acaba.** Sob MPL-2.0, uma modificação num arquivo *deste próprio projeto* seguia aberta sob MPL-2.0 mesmo distribuída dentro de uma Larger Work. Sob Apache-2.0, um fork downstream pode modificar um arquivo e fechá-lo, sem obrigação nenhuma de publicar a mudança. É exatamente o que está sendo trocado por adoção mais ampla, e adoção mais ampla **é** o objetivo declarado deste framework, não um efeito colateral racionalizado depois do fato.
2. **A compatibilidade com GPLv2 muda de sinal.** A MPL-2.0 carrega a cláusula "Secondary License" (License §3.3, Exhibit B não invocado no `LICENSE` deste projeto) que permite que Covered Software também seja redistribuído sob GPL-2.0, LGPL-2.1 ou AGPL-3.0, à opção do destinatário. **A Apache-2.0 não tem cláusula equivalente e é amplamente considerada** (a própria lista de compatibilidade da FSF, entre outras) **incompatível com a GPLv2**, embora **seja** compatível com a GPLv3 e posteriores. Um consumidor hipotético que fosse ele mesmo GPLv2 (não GPLv2-ou-posterior) e quisesse linkar estaticamente o glintfx perderia esse caminho. ✅ **Nenhum consumidor conhecido é afetado hoje**, verificado no repositório de cada consumidor, não perguntando a eles: o GusWorld não é GPLv2 (a licença dele é separada e não é afetada por esta decisão); o consumidor site Glyfesse é PHP+HTML com **zero superfície de linkagem** com o glintfx (`git grep '#include.*glintfx'` = 0, `git grep 'glintfx::'` = 1 menção em prosa editorial, `vendor/`/`third_party/`/`node_modules` = 0, pela própria verificação da fatia `APACHE-AVISO` registrada no `TODO.md`), então a pergunta sobre GPLv2 nem chega a se colocar para ele.

## Consequences / Consequências

**EN:** External devs gain the lowest-friction license for adopting glintfx (Apache-2.0 clears most corporate open-source allowlists without legal review); the project's own files no longer carry an automatic "stays open" guarantee for modifications, a real and named cost, not an oversight. The rotation is a **one-way door**: once external contributions start arriving under Apache-2.0's inbound=outbound rule (§5, recorded in `CONTRIBUTING.md`), reverting to MPL-2.0 (or anything else) would again require either universal contributor consent or a CLA, exactly the trap ADR-0007 named for the AGPL-to-MPL move. Three follow-on `TODO.md` fatias execute the mechanical and communication work this ADR authorizes but does not itself perform: `APACHE-HEADERS` (SPDX string rotation, ~383 files), `APACHE-TEXTOS` (`LICENSE`/`NOTICE`/doc-mention rotation beyond what this fatia already did for `LICENSE`/`NOTICE`/`docs/third_party_notices.md`/`CONTRIBUTING.md`), and `APACHE-AVISO` (consumer notice, gated on a real cut tag). ⚠️ **A packaging gap, found while preparing this ADR, flagged for whoever next touches `glintfx/CMakeLists.txt` (out of this ADR's own file scope):** `cmake --install` does not currently install `LICENSE` or `NOTICE` into the installed tree (zero `install(...)` reference to either, confirmed by reading every `install()` call in `glintfx/CMakeLists.txt`) — under Apache-2.0 §4, anyone redistributing that installed tree needs both files present in it. Recommend a human-lawyer review before the first external contribution is accepted under the new terms, per ADR-0007's own closing recommendation, unchanged by this rotation.

**PT:** Devs externos ganham a licença de menor atrito para adotar o glintfx (a Apache-2.0 passa pela maioria das listas de permissão jurídica corporativas sem revisão jurídica); os próprios arquivos do projeto deixam de carregar a garantia automática de "fica aberto" para modificações, um custo real e nomeado, não um descuido. A rotação é uma **porta de mão única**: assim que contribuições externas começarem a chegar sob a regra inbound=outbound da Apache-2.0 (§5, registrada no `CONTRIBUTING.md`), reverter para MPL-2.0 (ou qualquer outra coisa) voltaria a exigir consentimento universal de contribuidores ou um CLA, exatamente a armadilha que o ADR-0007 nomeou para a mudança de AGPL para MPL. Três fatias seguintes do `TODO.md` executam o trabalho mecânico e de comunicação que este ADR autoriza mas não executa ele mesmo: `APACHE-HEADERS` (rotação da string SPDX, ~383 arquivos), `APACHE-TEXTOS` (rotação de `LICENSE`/`NOTICE`/menções em doc além do que esta fatia já fez em `LICENSE`/`NOTICE`/`docs/third_party_notices.md`/`CONTRIBUTING.md`), e `APACHE-AVISO` (aviso ao consumidor, condicionado a uma tag de corte real). ⚠️ **Uma lacuna de empacotamento, achada ao preparar este ADR, sinalizada para quem próximo tocar o `glintfx/CMakeLists.txt` (fora do escopo de arquivo deste ADR):** o `cmake --install` hoje não instala `LICENSE` nem `NOTICE` na árvore instalada (zero referência `install(...)` a qualquer um dos dois, confirmado lendo toda chamada `install()` do `glintfx/CMakeLists.txt`), sob a Apache-2.0 §4 quem redistribui essa árvore instalada precisa dos dois arquivos presentes nela. Recomenda-se revisão por advogado humano antes da primeira contribuição externa ser aceita sob os novos termos, seguindo a própria recomendação de fechamento do ADR-0007, inalterada por esta rotação.

## Options considered / Opções consideradas

- **Apache-2.0 (chosen / escolhida)** — widest, most familiar permissive footprint; explicit patent grant kept (was already the MPL-2.0 draw); loses per-file copyleft and GPLv2 compatibility, both named above.
- **Keep MPL-2.0 / Manter MPL-2.0** — no new cost, but does not serve the framework's own stated wide-adoption goal any better than it already does; the trigger for revisiting was the goal sharpening (the framework2d direction, [ADR-0015](0015-framework-2d-atomized-architecture.md)), not a defect in MPL-2.0 itself. Rejected for this rotation, not because MPL-2.0 was wrong in 2026-06-28.
- **Dual-license MPL-2.0 OR Apache-2.0 going forward / Dual-license MPL-2.0 OU Apache-2.0 daqui pra frente** — would preserve both the copyleft option and GPLv2 compatibility for any future consumer that needs them. Rejected: real ongoing maintenance cost (two headers, two compliance stories) against no known present need; the 44 already-published MPL-2.0 tags already serve that role for anyone who needs to pin to them.
- **LGPL-3.0, AGPL-3.0** — already rejected in [[0007-license-mpl-2.0]] for reasons unchanged by this ADR (static-link friction and adoption-hostility respectively); not reconsidered here.
