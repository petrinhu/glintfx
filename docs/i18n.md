# i18n (I18N-1 reference and how-to)

> **EN:** `glintfx::I18n` API reference: catalog format, resolution order, CLDR-lite plurals, and known limitations. Diátaxis type: **how-to / reference**. Audience: a developer wiring translated strings into a glintfx-based game or app.
> **PT:** Referência da API `glintfx::I18n`: formato do catálogo, ordem de resolução, plurais CLDR-lite, e limitações conhecidas. Tipo Diátaxis: **how-to / reference**. Audiência: dev conectando strings traduzidas num jogo ou app baseado em glintfx.

`glintfx::I18n` (`glintfx/include/glintfx/i18n.hpp`) is the translation-catalog and locale-aware
lookup facade for the `GLINTFX_MODULE_I18N` atom (ADR-0015 (b) framework-2D architecture,
`I18N-1`). It depends on the C++ standard library ONLY -- no GL, no window, no RmlUi type -- so
it can be exercised by unit tests with no Xvfb, same independence class as the `audio` module.
The module is `ON` by default and genuinely `OFF`-able: `src/i18n.cpp` has zero callers anywhere
else in the library (nothing in `render_gl3.cpp`/`bootstrap.cpp`/`engine.cpp`/`ui_layer.cpp`/
`app.cpp` calls into `glintfx::I18n`), so compiling it out drops both the translation unit and
its symbols cleanly.

**Feeding a translated string INTO the UI is the consumer's job**, via the data-binding surface
that already exists (`create_data_model`/`bind_string`/`set_string`, see
[`docs/embed-integration.md`](embed-integration.md) section 6) -- this module never includes
anything from `ui` and has no RCSS/RML integration of its own.

## English

### Quick start

```cpp
glintfx::I18n i18n;
i18n.load_catalog_string(
    "[en-US]\n"
    "hud.title = My Game\n"
    "hud.lives.one = # life\n"
    "hud.lives.other = # lives\n"
    "[pt-BR]\n"
    "hud.title = Meu Jogo\n"
    "hud.lives.one = # vida\n"
    "hud.lives.other = # vidas\n");

i18n.set_locale("en-US");
i18n.tr("hud.title");            // "My Game"
i18n.tr_plural("hud.lives", 1);  // "1 life"

i18n.set_locale("pt-BR");
i18n.tr("hud.title");            // "Meu Jogo"
i18n.tr_plural("hud.lives", 0);  // "0 vida" -- pt's plural rule treats 0 as singular, see below
```

- `I18n()`/`~I18n()` are both `= default` -- no pImpl, no heap indirection: every member is
  standard-library data (`std::map`/`std::string`), so there is no third-party type to hide
  behind an opaque pointer.
- `load_catalog_string`/`load_catalog_file` may be called more than once; entries merge into the
  existing catalog, **last-write-wins per (locale, key) across calls** -- the mechanism a
  consumer uses to load a base catalog then a locale-specific override file.
- Neither loader crashes or throws on malformed input. `ok` in the returned `I18nLoadResult` is
  `false` ONLY on a fatal condition (`nullptr` text, an unreadable/nonexistent file, or a
  directory path passed as a file -- `load_catalog_file` probes for that last case explicitly via
  `std::ifstream::peek()`, since `is_open()` alone succeeds on a directory under Linux). A
  malformed *line* inside an otherwise-readable catalog is never fatal: it is skipped and counted
  in `lines_skipped`.

### Catalog format

Own, zero-dependency, UTF-8 text format -- not JSON/YAML/any third-party parser (decision
documented in `docs/superpowers/plans/2026-07-19-framework2d-i18n-module.md` section 7 item 2).

```
# a comment line -- '#' must be the FIRST non-whitespace character of the line.
[locale]                 # opens a section; matched case-insensitively at lookup time
key.with.dots = value    # leading/trailing whitespace around key and value is trimmed
key.one = # singular     # plural sub-keys, see "Plurals" below
key.other = # plural
```

- **Locale codes are case-insensitive at lookup**, but the display casing of the FIRST `[locale]`
  header seen is preserved verbatim for `locale()`/`locales()`.
- Always write the FULL BCP-47 tag (e.g. `pt-BR`/`en-US`), never a bare `pt`/`en`, UNLESS you
  deliberately want that section to serve as the base-language fallback for every region (see
  "Resolution order" below) -- this is stated as an explicit anti-over-engineering principle in
  the header (`locale != language`).
- A line that is not blank, not a comment, not a well-formed `[locale]` header (missing the
  closing `]`, or an empty name), and not a well-formed `key = value` pair (no `=`, or an empty
  key) is malformed: skipped and counted in `lines_skipped`. When a malformed section header is
  hit, the PREVIOUS section (if any) stays open, so one bad header line does not silently
  misattribute the rest of an otherwise well-formed file. A `key = value` line seen before any
  `[locale]` header has nowhere to go and is also skipped+counted.
- **Escapes are deliberately minimal** (anti-over-engineering principle, not grown past real
  need): inside a value, `\\` -> `\`, `\n` -> newline, `\t` -> tab. Any other backslash sequence
  is copied through literally, both characters -- an unrecognised escape is never a parse error.

### API reference

| Method | Returns | Notes |
| :--- | :--- | :--- |
| `load_catalog_string(const char* text)` | `I18nLoadResult` | `text == nullptr` returns `{.ok = false}` without touching the catalog. |
| `load_catalog_file(const char* path)` | `I18nLoadResult` | `path == nullptr`, an unreadable file, or a directory path all return `{.ok = false}`. |
| `set_locale(const char* locale_code)` | `bool` | `false` (no change) if `locale_code` is `nullptr`/empty. The locale need not already exist in a loaded catalog. |
| `locale()` | `const std::string&` | As last set via `set_locale()`, or `""` if never set. |
| `set_fallback_locale(const char* locale_code)` | `bool` | Same validation as `set_locale()`. Optional -- if never set, resolution skips step 3/4 below. |
| `fallback_locale()` | `const std::string&` | As last set, or `""` if never set. |
| `locales() const` | `std::vector<std::string>` | Every locale with at least one entry loaded, original casing, sorted case-insensitively. Intended for a language picker / settings menu. |
| `tr(const char* key) const` | `std::string` | Bare lookup, no plural/placeholder handling. `key == nullptr` returns `""`. Never crashes on a missing key. |
| `tr_plural(const char* key, long long n) const` | `std::string` | Selects `.one`/`.other`, substitutes `#` with `n`'s decimal digits. `key == nullptr` returns `""`. |

### Resolution order

`tr()`/`tr_plural()` never crash and never return an empty string for a non-null key. Both walk
the same five steps, in order, stopping at the first hit:

1. The exact active locale.
2. The active locale's base language (the part before `-`, e.g. `pt-BR` -> `pt`) -- only if the
   active locale itself has a region tag (an active locale of `en` with no `-` has no separate
   step 2; it is not re-tried for nothing).
3. The exact fallback locale, if one was set via `set_fallback_locale()`.
4. The fallback locale's base language, under the same condition as step 2.
5. The bare key itself, verbatim -- the last-resort signal that a translation is missing,
   deliberately visible in the rendered UI rather than silently blank.

`tr_plural()` additionally falls back from the `.one` form to the `.other` form **within each of
steps 1-4** before advancing to the next step, because `other` is the CLDR-guaranteed catch-all
category every locale defines. `tr_plural("timer", 1)` against a catalog that only defines
`timer.other` (no `timer.one`) therefore still resolves under the `en` step, rather than falling
through to a fallback locale or the bare key.

### Plurals (CLDR-lite)

A pluralizable concept is stored as two catalog entries under a shared base key, `<key>.one` and
`<key>.other` (ICU-lite category names). This module supports exactly these two categories, by
scope choice, not because the shipped locales lack the others -- `pt` genuinely has a CLDR v48
`many` category (exact multiples of 1,000,000) that collapses into `other` here by design (a HUD
showing "1,000,000 lives" is not a real game scenario). `few`/`zero`/`two` do not apply to either
`en` or `pt` in CLDR v48.

Plural rule source: [Unicode CLDR Language Plural Rules chart v48](https://www.unicode.org/cldr/charts/48/supplemental/language_plural_rules.html),
fetched and read directly (cited verbatim in `glintfx/src/i18n.cpp`'s header comment):

| Base language | `one` | `other` |
| :--- | :--- | :--- |
| `en` | exactly 1 | everything else (0, 2-16, 100, ...) |
| `pt` | 0 or 1 | everything else (2-17, 100, ...) |
| any other/unrecognised base language | exactly 1 (falls back to the `en` rule) | everything else |

The category is selected from the active locale's **base language** (`pt-BR` -> `pt`), never a
region-specific rule set, and off the count's **absolute value** (CLDR cardinal rules key off
`|n|`; a negative count is not a separate case). Inside a `.one`/`.other` value, every literal `#`
character is the count placeholder (ICU convention) -- `tr_plural()` replaces every `#` with the
base-10 digits of `n`, sign included (e.g. `n = -3` -> `"-3"`), including at `LLONG_MIN`, computed
without `std::llabs()`/unary `-` (both undefined behaviour there). Because of this substitution
rule, a `.one`/`.other` value cannot contain a literal `#` as ordinary text -- use `tr()` for
strings that need one.

### Known limitations

- **Not the full ICU `plural` grammar.** Only the `one`/`other` categories are selected, and only
  for `en`/`pt` base languages (see the table above); any other locale silently uses the `en`
  rule rather than its own CLDR category set. If a shipped locale genuinely needs `few`/`many`,
  extending the table in `glintfx/src/i18n.cpp`'s `plural_category_for()` is the natural next
  slice, not a redesign.
- **ASCII-only case-folding**, for both locale codes and catalog keys -- both are always ASCII in
  this module's own grammar (BCP-47 tags, dotted keys), so a full Unicode case-fold (an ICU-class
  dependency) is deliberately out of scope.
- **No lazy/streaming catalog loading.** `load_catalog_file()` reads the whole file into memory
  before parsing (`std::ostringstream buffer; buffer << file.rdbuf();`) -- fine for a
  human-editable text catalog, not designed for a multi-megabyte localization dump.
- **No plural-category caching or memoization** -- every `tr_plural()` call re-derives the
  category from `n`. Not a measured hot path for a catalog of realistic size (a handful of keys
  per locale, per the resolution-order implementation's own reasoning).
- **No RCSS/RML integration of its own.** This module produces `std::string`; getting that string
  onto screen is the consumer's job via the pre-existing data-model surface (see the intro above).

## Português

### Início rápido

```cpp
glintfx::I18n i18n;
i18n.load_catalog_string(
    "[en-US]\n"
    "hud.title = My Game\n"
    "hud.lives.one = # life\n"
    "hud.lives.other = # lives\n"
    "[pt-BR]\n"
    "hud.title = Meu Jogo\n"
    "hud.lives.one = # vida\n"
    "hud.lives.other = # vidas\n");

i18n.set_locale("en-US");
i18n.tr("hud.title");            // "My Game"
i18n.tr_plural("hud.lives", 1);  // "1 life"

i18n.set_locale("pt-BR");
i18n.tr("hud.title");            // "Meu Jogo"
i18n.tr_plural("hud.lives", 0);  // "0 vida" -- a regra de plural do pt trata 0 como singular, ver abaixo
```

- `I18n()`/`~I18n()` são os dois `= default` -- sem pImpl, sem indireção de heap: todo membro é
  dado de biblioteca padrão (`std::map`/`std::string`), então não há tipo de terceiro pra esconder
  atrás de um ponteiro opaco.
- `load_catalog_string`/`load_catalog_file` podem ser chamadas mais de uma vez; entradas se
  fundem no catálogo existente, **último-escreve-vence por (locale, chave) entre chamadas** -- o
  mecanismo que um consumidor usa pra carregar um catálogo base e depois um arquivo de override
  específico de locale.
- Nenhum dos dois loaders crasha ou lança exceção com input malformado. `ok` no `I18nLoadResult`
  retornado é `false` SÓ numa condição fatal (texto `nullptr`, arquivo ilegível/inexistente, ou um
  caminho de diretório passado como arquivo -- `load_catalog_file` sonda esse último caso
  explicitamente via `std::ifstream::peek()`, já que `is_open()` sozinho tem sucesso num
  diretório no Linux). Uma *linha* malformada dentro de um catálogo por outro lado legível nunca é
  fatal: é pulada e contada em `lines_skipped`.

### Formato do catálogo

Formato de texto próprio, zero-dependência, UTF-8 -- não JSON/YAML/nenhum parser de terceiro
(decisão documentada em `docs/superpowers/plans/2026-07-19-framework2d-i18n-module.md` seção 7
item 2).

```
# uma linha de comentário -- '#' precisa ser o PRIMEIRO caractere não-espaço da linha.
[locale]                 # abre uma seção; comparado sem diferenciar maiúsculas/minúsculas no lookup
chave.com.pontos = valor # espaço em branco antes/depois de chave e valor é removido
chave.one = # singular   # sub-chaves de plural, ver "Plurais" abaixo
chave.other = # plural
```

- **Códigos de locale não diferenciam maiúsculas/minúsculas no lookup**, mas a grafia de exibição
  do PRIMEIRO cabeçalho `[locale]` visto é preservada ao pé da letra para `locale()`/`locales()`.
- Sempre escreva a tag BCP-47 COMPLETA (ex.: `pt-BR`/`en-US`), nunca um `pt`/`en` cru, A MENOS que
  você deliberadamente queira que aquela seção sirva de fallback de idioma-base pra toda região
  (ver "Ordem de resolução" abaixo) -- isso é declarado como princípio explícito anti-OE no
  cabeçalho (`locale != idioma`).
- Uma linha que não é branca, não é comentário, não é um cabeçalho `[locale]` bem-formado (falta
  o `]` de fechamento, ou nome vazio), e não é um par `key = value` bem-formado (sem `=`, ou chave
  vazia) é malformada: pulada e contada em `lines_skipped`. Quando um cabeçalho de seção
  malformado é encontrado, a seção ANTERIOR (se houver) continua aberta, então uma única linha de
  cabeçalho ruim não atribui mal silenciosamente o resto de um arquivo por outro lado bem-formado.
  Uma linha `key = value` vista antes de qualquer cabeçalho `[locale]` não tem onde ir e também é
  pulada+contada.
- **Escapes são deliberadamente mínimos** (princípio anti-OE, não crescido além da necessidade
  real): dentro de um valor, `\\` -> `\`, `\n` -> nova linha, `\t` -> tab. Qualquer outra sequência
  de barra invertida é copiada literalmente, os dois caracteres -- um escape não reconhecido nunca
  é erro de parse.

| Método | Retorna | Notas |
| :--- | :--- | :--- |
| `load_catalog_string(const char* text)` | `I18nLoadResult` | `text == nullptr` retorna `{.ok = false}` sem tocar no catálogo. |
| `load_catalog_file(const char* path)` | `I18nLoadResult` | `path == nullptr`, um arquivo ilegível, ou um caminho de diretório retornam `{.ok = false}`. |

| `set_fallback_locale(const char* locale_code)` | `bool` | Mesma validação de `set_locale()`. Opcional -- se nunca definida, a resolução pula o passo 3/4 abaixo. |
| `fallback_locale()` | `const std::string&` | Tal como definida, ou `""` se nunca definida. |
| `locales() const` | `std::vector<std::string>` | Todo locale com ao menos uma entrada carregada, grafia original, ordenado sem diferenciar maiúsculas/minúsculas. Pensado pra um seletor de idioma / menu de configurações. |
| `tr(const char* key) const` | `std::string` | Lookup cru, sem tratamento de plural/placeholder. `key == nullptr` retorna `""`. Nunca crasha numa chave ausente. |
| `tr_plural(const char* key, long long n) const` | `std::string` | Seleciona `.one`/`.other`, substitui `#` pelos dígitos decimais de `n`. `key == nullptr` retorna `""`. |

### Ordem de resolução

`tr()`/`tr_plural()` nunca crasham e nunca retornam string vazia para uma chave não-nula. Ambas
percorrem os mesmos cinco passos, em ordem, parando na primeira que acerta:

1. O locale ativo exato.
2. O idioma-base do locale ativo (a parte antes do `-`, ex.: `pt-BR` -> `pt`) -- só se o locale
   ativo em si tiver tag de região (um locale ativo `en` sem `-` não tem um passo 2 separado; não
   é re-tentado à toa).
3. O locale de fallback exato, se um foi definido via `set_fallback_locale()`.
4. O idioma-base do locale de fallback, sob a mesma condição do passo 2.
5. A própria chave, ao pé da letra -- o sinal de último recurso de que falta uma tradução,
   deliberadamente visível na UI renderizada em vez de silenciosamente em branco.

`tr_plural()` adicionalmente cai da forma `.one` pra forma `.other` **dentro de cada um dos
passos 1-4** antes de avançar pro próximo passo, porque `other` é a categoria catch-all garantida
pelo CLDR que todo locale define. `tr_plural("timer", 1)` contra um catálogo que só define
`timer.other` (sem `timer.one`) portanto ainda resolve dentro do passo `en`, em vez de cair pra um
locale de fallback ou pra chave crua.

### Plurais (CLDR-lite)

Um conceito pluralizável é guardado como duas entradas de catálogo sob uma chave-base
compartilhada, `<chave>.one` e `<chave>.other` (nomes de categoria ICU-lite). Este módulo suporta
exatamente estas duas categorias, por escolha de escopo, não porque os locales entregues careçam
das outras -- o `pt` de fato tem uma categoria `many` no CLDR v48 (múltiplos exatos de
1.000.000) que colapsa em `other` aqui por design (um HUD mostrando "1.000.000 vidas" não é um
cenário real de jogo). `few`/`zero`/`two` não se aplicam nem a `en` nem a `pt` no CLDR v48.

Fonte da regra de plural: [gráfico Unicode CLDR Language Plural Rules v48](https://www.unicode.org/cldr/charts/48/supplemental/language_plural_rules.html),
buscado e lido diretamente (citado ao pé da letra no comentário de cabeçalho de
`glintfx/src/i18n.cpp`):

| Idioma-base | `one` | `other` |
| :--- | :--- | :--- |
| `en` | exatamente 1 | todo o resto (0, 2-16, 100, ...) |
| `pt` | 0 ou 1 | todo o resto (2-17, 100, ...) |
| qualquer outro idioma-base/não reconhecido | exatamente 1 (cai pra regra do `en`) | todo o resto |

A categoria é selecionada a partir do **idioma-base** do locale ativo (`pt-BR` -> `pt`), nunca um
conjunto de regra específico de região, e sobre o **valor absoluto** da contagem (as regras
cardinais do CLDR usam `|n|`; uma contagem negativa não é um caso separado). Dentro de um valor
`.one`/`.other`, todo caractere `#` literal é o placeholder de contagem (convenção ICU) --
`tr_plural()` substitui todo `#` pelos dígitos base-10 de `n`, sinal incluído (ex.: `n = -3` ->
`"-3"`), inclusive em `LLONG_MIN`, calculado sem `std::llabs()`/unário `-` (ambos comportamento
indefinido ali). Por causa dessa regra de substituição, um valor `.one`/`.other` não pode conter
um `#` literal como texto comum -- use `tr()` para strings que precisem de um.

### Limitações conhecidas

- **Não é a gramática `plural` completa do ICU.** Só as categorias `one`/`other` são
  selecionadas, e só para idiomas-base `en`/`pt` (ver a tabela acima); qualquer outro locale
  silenciosamente usa a regra do `en` em vez do próprio conjunto de categorias CLDR. Se um locale
  entregue genuinamente precisar de `few`/`many`, estender a tabela em `plural_category_for()` de
  `glintfx/src/i18n.cpp` é a próxima fatia natural, não um redesenho.
- **Case-folding só-ASCII**, tanto para códigos de locale quanto para chaves de catálogo -- os
  dois são sempre ASCII na gramática própria deste módulo (tags BCP-47, chaves com pontos), então
  um case-fold Unicode completo (uma dependência classe ICU) está deliberadamente fora de escopo.
- **Sem carregamento de catálogo preguiçoso/em streaming.** `load_catalog_file()` lê o arquivo
  inteiro pra memória antes de fazer parse (`std::ostringstream buffer; buffer << file.rdbuf();`)
  -- ótimo pra um catálogo de texto editável a mão, não desenhado pra um dump de localização de
  vários megabytes.
- **Sem cache/memoização de categoria de plural** -- toda chamada a `tr_plural()` re-deriva a
  categoria a partir de `n`. Não é um hot path medido pra um catálogo de tamanho realista (um
  punhado de chaves por locale, pelo próprio raciocínio da implementação da ordem de resolução).
- **Sem integração RCSS/RML própria.** Este módulo produz `std::string`; colocar essa string na
  tela é trabalho do consumidor via a superfície de data-model pré-existente (ver a introdução
  acima).
